For reviewers of any unittest or Django change

Did this change break anything that worked before?

Paste the test log from before the change (the baseline) and the log from after it. OnRamp separates failures the code already had from new regressions, and writes a verdict you can paste into the pull request.

  • Runs fully in your browser. Nothing is uploaded.
  • Reads Django manage.py test -v 2 and python -m unittest -v output
  • Fail-closed: an incomplete log gives no verdict

    Verdict file (JSON)

    The JSON file holds the verdict, the parse problems, the per-category test IDs and a SHA-256 of each pasted log. Attach it to the review as evidence.

    How the verdict is decided

    Each test ID in the baseline is compared with the same ID in the after run. FAIL and ERROR count as failing. An unexpected success counts as FAIL, and an expected failure counts as PASS.

    Categories

    • Regression: passed in the baseline, fails after the change.
    • New failure: a test that is not in the baseline and fails after the change.
    • Fixed: failed in the baseline, passes after the change.
    • Inherited: failed in the baseline and still fails. The change did not cause it.
    • Not run: in the baseline, missing from the after run. A not-run test never counts as fixed.
    • Skipped: in the baseline, skipped in the after run.

    Fail-closed rules

    • Inconclusive if either log has no Ran N tests line, no final OK/FAILED line, a test count that differs from the parsed result lines, or a final status that disagrees with the per-test results. No "fixed" and no "0 regressions" is reported then.
    • Inconclusive if either log has zero parsed test results.
    • Targeted run only if any baseline test is missing from the after run. A partial run cannot prove the full suite.
    • Full run, 0 regressions only if every baseline test ran and no test went from passing to failing, and no new test fails.

    The parser is the same one the Evidence Explorer uses. It is a JavaScript port of the kit's Python normalizer, checked against the Python output on every fixture log. It does not read pytest output.
