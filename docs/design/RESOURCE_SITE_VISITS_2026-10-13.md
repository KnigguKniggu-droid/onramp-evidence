# Resource site visits and the guidance applied (the team, 2026-10-13)

Each official site was opened in Chrome and read. Where a site offers free prompts, guides or open-source code, the guidance was used. Where content is paywalled or behind sign-in, only the public description was used. No accounts were created, nothing was bought, cookie banners were declined, and no paid prompt or template was copied.

| Site | What was accessible | Guidance taken | Where it is applied |
|---|---|---|---|
| **GetLayers** (getlayers.ai, /docs, /layer/roadmap-ascent) | Docs and public layer descriptions. Layer prompts say "Upgrade to unlock" (paid). | Docs: a generic AI page is "the average of everything" (centred hero, three cards); start from a layer of craft, and give each layer a job. Public description of the *Roadmap Ascent* layer: a glowing node travels a spine and lights each milestone. | Hero built as purpose-labelled layers. The blind-fix steps have a glowing node that travels the spine with scroll and lights each step (`.steps.seq::after`, `--prog`). |
| **MotionSites** (motionsites.org, /sections/how-it-works, /prompts/how-it-works-03-velara) | Catalogue and the public preview of free prompts. The full prompt text needs sign-in, even for free ones. | The free "How it Works 03 Velara" preview describes a three-step section where each step pairs a numbered text column with an animated terminal-style mockup, with scroll-triggered entrance. | Each blind-fix step now has a terminal panel showing **real excerpts** from the evidence files (seal JSON, the failing test, Bob's diff plus the passing run, the upstream line), revealed line by line as you scroll. |
| **Awesmos** (awesmos.com, /learn guides) | Free guides: "Best AI prompts for landing pages" and "Vibe coding". Templates are paid. | Describe structure and hierarchy first, style second. Keep a reusable brand-context block. Refine in separate passes (structure, copy, style, motion). Test mobile before calling it done. | `docs/design/BRAND_CONTEXT.md` (new). This pass followed structure → copy → style → motion. Mobile captured at 320 and 375 px. |
| **Magic UI** (magicui.design; MIT source on GitHub) | Free docs and MIT source for Terminal, Code Comparison, Scroll Progress and Dot Pattern | Terminal: lines appear in sequence. Code comparison: focus the changed lines and dim the context. Scroll progress: a thin bar scaled by page progress. Dot pattern: a subtle grid background. | Terminal sequence in the steps. Diffs dim context lines on hover or focus and tint the -/+ lines. Scroll-progress bar in the nav. Dot grid behind the demo. All re-implemented in vanilla CSS/JS; no React or Magic UI code copied. |
| **21st.dev** | Landing page only. The catalogue and MCP need sign-in or an API key. | Category vocabulary only (animated heroes, shaders, liquid & metal, backgrounds) | — (no component used; no key requested) |
| **Paper** (paper.design) | Landing page | "Good bye lorem ipsum": design with real content and data; one source of truth for tokens | All copy and numbers are generated from evidence. Tokens live only in `:root`. |
| **GSAP** (gsap.com/resources/st-mistakes) | Free docs | Don't use `scroll-behavior: smooth` with ScrollTrigger. Refresh after dynamic content. Use `clamp()` starts to avoid jumps on load. Don't nest ScrollTriggers in timelines. | `html.fx{scroll-behavior:auto}`, with smooth anchors done in JS. `ScrollTrigger.refresh()` runs on page-height change. `clamp()` on reveal and sequence starts. One ScrollTrigger per timeline. |
| **three.js** (manual: Rendering on Demand, Picking) | Free manual | Render only when something changes, not in a constant loop. Use a Raycaster to pick objects under the pointer. | The suite map renders on demand and idles. Hovering (or tapping) a dot shows its test id and classification. |
| **Motion** (motion.dev/docs/react-accessibility) | Free docs | Under reduced motion, keep educational transitions as opacity fades; turn off parallax and autoplay. | The reduced-motion CSS keeps 150 ms opacity and colour transitions; the verdict fades. Parallax and auto-rotation stay off. |
| **Webflow** (webflow-way/design-systems/interactions) | Free guide | Durations: 150–300 ms micro, 300–600 ms UI, 500–800 ms entrances. Start with intent. One or two eases. Animate only transform and opacity, not filters or shadows. Long decorative motion must be pausable. Name interactions "Trigger Target Action". | Hover transitions at 180 ms. Entrances at 500 ms. Ease family power2/power3. Blur filter removed earlier. A **Pause motion** control (bottom right) pauses the hero drift, beams and 3D rotation, and parallax. `fx.js` sections are named that way. |
| **UI UX Pro Max** (uupm.cc; repo at 7246805) | Site, plus the MIT skill run locally (`search.py --design-system`; stdlib only, checked for network/exec first; nothing installed) | Recommendation for this product: dark technical style, IBM Plex Sans with a mono, minimal glow, visible focus, reduced motion. Pre-delivery checklist: no emoji/glyph icons (use SVG), cursor-pointer on clickables, 150–300 ms hover states, 4.5:1 contrast, responsive at 375/768/1024/1440. | ▶ and ♪ glyph icons replaced with inline SVG. Hover transitions added. `cursor:pointer` on cards, scenarios, toggles and summaries. Contrast 0 failures. QA includes 1024 px. |
| **Awwwards** (single-page nominees) | Gallery thumbnails | Strong typographic contrast plus one repeated visual motif, e.g. a dot-matrix texture on developer-tool sites. Nothing copied. | The dot-grid motif (demo background) echoes the dots of the suite map. |
| **Threlte** | Landing page | A Svelte 3D framework. It doesn't fit this vanilla page. | — |
| **Vectary**, **Jitter** | Landing pages; both need accounts | Jitter suits the demo **video** (motion titles) | Noted for the video track. Nothing on the site. |
| **HyperFrames** | Free docs | HTML → deterministic video, built by an agent | Candidate for the demo video. Never used to fabricate Bob sessions. |
